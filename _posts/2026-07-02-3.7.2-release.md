Pachli 3.7.2 is now available. This release fixes a crash processing corrupt notification data and enhances the "header" shown above posts that are replies.

<!--more-->

### Updates to translations

Languages with updated translations are:

- Kabyle by [ButterflyOfFire](https://github.com/pachli/pachli-android/commits?author=boffire@users.noreply.hosted.weblate.org)

If you would like to help improve Pachli's translation in to your language there's [information on how you can contribute](https://github.com/pachli/pachli-android/blob/main/docs/contributing/translate.md).

## Significant bug fixes

### Don't crash on corrupt notification data

[Lucas Treffenstädt](https://toot.treffenstaedt.de/@lucas) reported a crash (#[2366](https://github.com/pachli/pachli-android/issues/2366)) when Pachli was processing corrupt cached notification data. This is their first contribution to Pachli.

Fixed with #[2368](https://github.com/pachli/pachli-android/pull/2368)

### Show data about the account being replied to in more cases

A header appears over posts to show why you're seeing the post. If it's a reply it's supposed to say either

- "X replied to Y"

if Pachli has a cached copy of the account being replied to, or

- "X replied"

if Pachli doesn't have those details

While investigating the previous issue I noticed this was only ever showing "X replied", because the cached data wasn't being used correctly. It's a small thing, but this now works as intended (#[2367](https://github.com/pachli/pachli-android/pull/2367)).
