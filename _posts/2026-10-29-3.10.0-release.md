Pachli 3.10.0 is now available. This release can warn you before boosting posts with missing media descriptions, improves support for Cloudflare bot detection, and more.

<!--more-->

## New features and other improvements

### Add preference to warn before boosting posts missing media descriptions

[Pixy's Journey](https://beige.party/@PixysJourney) [suggested](https://github.com/pachli/pachli-android/issues/750) a Fediverse accessibility improvement; Pachli could show a warning before boosting a post with media attachments (images, video, etc) where one or more of the attachments was missing a description.

[Jaressen Kyle Salcedo](https://mastodon.social/@jksalcedo) saw this request and lead the work to implement this feature (#[2388](https://github.com/pachli/pachli-android/pull/2388) and #[2473](https://github.com/pachli/pachli-android/pull/2473)), marking their first contribution to Pachli. Thanks Jaressen! 

The "Show confirmation before boosting" preference used to be an on/off toggle. Now it has a third state where the confirmation will be shown if the post is missing media descriptions. The confirmation menu has also been updated to flag missing descriptions any time the menu is shown, so if you have confirmation set to "Always confirm" you will also be informed.

The accessibility actions have been updated to also show this information.

### Return to Pachli after navigating away when writing a post

Since Pachli 3.3.0 you can [write multiple posts simultaneously, and switch between them](/pachli/2025/12/30/3.3.0-release.html#allow-multiple-simultaneous-compose-tasks).

[user-name-pc](https://github.com/user-name-pc) reported a confusing Android behaviour with this (#[2409](https://github.com/pachli/pachli-android/issues/2409), their first contribution to Pachli).

Briefly, if you created a post with these steps:

- Open Pachli
- Tap the "Compose" button
- Write the post
- Tap the "Send" button

then Android remembers the "Compose" screen was started by Pachli, and returns you back to Pachli after you hit "Send".

However, if you did this:

- Open Pachli
- Tap the "Compose" button
- Start writing the post
- Switch to another app; e.g., a browser to find a link, or copy some text
- Switch back to the Pachli post editor
- Tap the "Send" button

then Android forgets the "Compose" screen was started by Pachli, and unceremoniously dumps you back to the main Android launcher. If you're not expecting this in can appear as though Pachli has crashed.

This seems to be an Android bug, as other apps, including GMail, show the same behaviour.

This is improved in #[2483](https://github.com/pachli/pachli-android/pull/2483). Now, after you hit the "Send" button you are returned to the previous Pachli screen.  

### Support Cloudflare Turnstile bot detection when logging in

[@ronsboy67@mas.to](https://mas.to/@ronsboy67) [reported](https://mas.to/@ronsboy67/117505310005798994) an issue logging in to their account at [https://mas.to](https://mas.to).

Investigation showed [https://mas.to](https://mas.to) uses [Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/) as a CAPTCHA alternative to try and prevent bots from scraping their servers.

Unfortunately, the mechanisms Cloudflare use are strongly biased towards complete browsers, and not the stripped-down browser Pachli normally uses when you're logging in, causing the login process to fail.

Handily, Cloudflare provide some [documentation for mobile apps](https://developers.cloudflare.com/turnstile/get-started/mobile-implementation/) with suggestions to make the process more reliable. Pachli can now reliably log in to servers using Turnstile.

## Significant bug fixes

### Allow compose UI to take full display height on large devices

[Terence Eden](https://mastodon.social/@edent) reported [#2471](https://github.com/pachli/pachli-android/issues/2471) (their first contribution to Pachli) the editor when writing a post was the wrong height (too small) on large devices, or smaller devices where you had configured Android to shrink the UI size.

[Ibrahim Al-Alali](https://mastodon.social/@iboalali) also provided helpful debugging information. This was fixed in #[2482](https://github.com/pachli/pachli-android/pull/2482).
